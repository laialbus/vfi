  - It reads every file ending in `.rs` under `crates/analyze/`, found by
    walking the directory on each run, minus everything under `tests/`,
    `benches/` and `examples/`, and minus each item that stands under exactly
    `#[cfg(test)]`, from the attribute through that item's closing brace or
    semicolon. Any other `cfg` is read. `crates/analyze/build.rs` is read when
    it exists. It goes red on reading no file at all, and on a file it cannot
    lex, naming the file, rather than skipping it.
  - It goes red on each numeric literal that stands outside the three places
    `docs/adr/what-analyze-takes-and-returns.md` fixes and is not on the
    allowlist, listing every one and not only the first, each as
    `<file>:<line>: <literal as written>`. The three places are any file under
    `crates/analyze/src/constants/`, any file under
    `crates/analyze/src/settings/`, and in `crates/analyze/src/method.rs` the
    literal initialising `METHOD_VERSION` in the one-line item
    `const METHOD_VERSION: <type> = <literal>;`, `pub` or not. Every other
    literal in `method.rs` is read.
  - The allowlist is written once beside the check, each entry with its
    reason, as `denied_packages` is. It holds zero, spelled `0` or `0.0`, and
    one, spelled `1` or `1.0`, each with an optional type suffix and an
    optional single underscore before it. A literal is compared after its
    suffix and that underscore are removed, and a literal behind a unary
    minus is read without the minus. Every other spelling of the two values
    is red, `0x1`, `0b0`, `1e0`, `1.`, `1.00`, `00` and `0_0` among them.
  - Each form `docs/adr/bare-literal-lint.md` decides is read as it decides.
    In are integer and float literals in every base, with an exponent, a
    suffix or underscores; an array length or repeat count; a slice index or
    range; a literal inside a `const` or `static` outside the three places;
    inside an attribute; inside a macro's arguments or a `macro_rules!` body;
    in a match pattern, an enum discriminant or a const generic argument. Out
    are a tuple index, the contents of a string, character or byte literal,
    comments including doc comments, and digits inside an identifier.
  - The identifier `preset`, as a whole token outside strings and comments,
    in any file it reads outside `crates/analyze/src/settings/`, is red as
    `<file>:<line>: preset`. The name is written once beside the check. The
    check is also red when `crates/analyze/src/settings/` holds a `.rs` file
    and none of them holds `fn preset`. While `settings/` does not exist,
    nothing about it is checked.
  - The proofs the record lists run under the runner's existing `prove`.
    `accept_literals` stays green carrying a literal in each of the three
    places, with the `2` in `METHOD_VERSION`, a derivation file holding `1`
    and `0.0`, and one of each form decided out, which is a tuple index, a
    number in a string, a number in a comment, a `#[cfg(test)]` module holding
    a literal, and a file under `tests/` holding a literal and calling
    `Settings::preset`. `violate_literals` plants `0.15` in a derivation file
    and `must_name` pins the file, line and literal. `violate_literals_preset`
    plants a call to `Settings::preset()` in a derivation file.
    `violate_literals_preset_gone` plants a `settings/` file with no
    `fn preset`. `violate_literals_unreadable` plants an unterminated block
    comment. `violations` names all four for `literals`.
  - What the check cannot see is said beside it, as `egress` says it of its
    own, and at the least covers the seven items the record lists under that
    heading.
  - It walks `crates/analyze/` on its own. It takes no name from
    `ambient_names` and gives it none, and the two checks share no list and
    no walk.
  - 'Nothing proved gets narrower. Every existing gate, proof and
    `scripts/tests/` case still passes, and no entry leaves `denied_packages`,
    `allowed_edges`, `ambient_names` or the expected gate set.'
  - No crate, manifest, lockfile or source under `crates/` changes. The
    analyze source on main today passes as it stands. The diff changes

`docs/adr/bare-literal-lint.md`, accepted on 2026-10-05, is the record for
the lint anchor 5's enforcement clause names, and GOALS.md's sixth and
seventh M5 criteria rest on it: every methodology constant is named, defined
once and cited, and every free parameter arrives as a setting. The record
decides the gate's name, what it reads, the three places, the allowlist,
every form, the preset constructor's name and the proof set. This task
builds exactly that and decides nothing the record leaves open; its two open
questions, a unit scale and a written precision, are a metric task's to
raise.

`scripts/gates.sh` is protected and grantable, so this task lists it under
`owns`. The pull request merges only with the `human-approved` label, applied
by a human hand. It runs alone because the gate runner is a shared surface.

It depends on M5-04, merged at fda6f0e, because the record places `literals`
after `ambient` and the two walk the same crate on their own. The analyze
skeleton (M5-15) waits on this, so that the first file under `settings/` and
the first `METHOD_VERSION` land under the gate that reads them.

If the lexer cannot read a form as the record decides it without admitting a
form the record decides out, or without a third allowlist value, that is an
escalation, not a wider list.
