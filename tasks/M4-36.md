The second of the two rules `crates/normalize/src/lib.rs` says the crate does
not carry. Rule 1 of the accepted `docs/adr/period-alignment.md` stands
unchanged — the record superseding Rule 3 says so in as many words — and it
states this rule whole, down to the count it re-derives from the merged
fixture. This task transcribes it.

It follows M4-35 rather than running beside it, for the reason Rule 1 reads
the way it does: a period is the filer's when a concept resolves to a `Value`
at it, and which value stands at a period is Rule 3's answer over every filing
that answers it. Asked of one filing's attempt instead, the set would depend on
which filing happened to be asked, which is the thing Rule 2 already refuses.
Both tasks own the same crate, so they are ordered rather than left to collide.

Why the clause about the cover page is in the acceptance and not left to the
implementation: on this fixture, ten of the 18 strays are cover dates, one per
filing, each equal to that filing's own `filed`. An entry admitted there would
put ten periods in the set that no statement of the filer covers, and every one
of them would look like a real instant.

Not in this diff: the shape the stage hands analyze, which is a contract
version and is M4-37; the wiring of the stage end to end over a filer's
history; and the six normalize golden fixtures, which wait on the wiring.
