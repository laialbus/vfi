`docs/adr/fetch-normalize-v2.md` is accepted, and it decides two things about
the boundary that nothing yet does. A filer's `cik` crosses in one spelling, ten
digits left-padded whichever way the document spelled it, because the registry
binds a filer to exactly that string and a second spelling would find no
override file and look like a filer that has none. And each fact carries the
date its filing's period of report ends, joined from the submissions history,
because the accepted alignment record's condition for admitting the cover-page
share count names that field and at v1 cannot be stated. One version carries
both, so the contract moves once. This publishes that version and moves
everything compiled against v1 onto it.

The record is precise about what a fixture can pin for each field, and the
acceptance repeats it rather than leaving the run to choose. For the key, a
hand-written number-spelled document in the crate's own test file pins the read
and the padding the day the bytes move; the recording from a real number-spelled
filer, which the record says is what pins it against EDGAR's own bytes, is M4-26,
queued behind this so that nothing downstream reads the key before both hold. For
the report period end, the four checks are all mechanical and all available from
the pair of recordings the repository already holds for one filer — which is why
the history that case joins to must be the submissions recording already in the
tree and not a fresh one: a fresh one would name the tenth filing, and the check
that the field is empty where the history does not name the filing would have
nothing left to hold. What no fixture can check — that `reportDate` is the
period a filing is about — the record says plainly, and this task does not owe a
fifth check.

The other facts case has no history recorded beside it, so this diff records
one, through the recorder and with the sandbox off for that one command, as
M4-07 and M4-20 did and for the same reason. A facts case carrying the field
empty on every fact because its history was never recorded would pin the join's
degenerate case for a filer whose history is a request away.

Exclusive because it publishes a contract, which WORKPLAN.md single-threads.
The hook grants the write to `contracts/` only from this file as committed on
origin/main, and a protected path that changes needs the human-approved label at
merge — the same two mechanics M4-03 ran under.

Not in this diff: the number-spelled recording, which is M4-26; anything inside
`crates/normalize/src/`, where admitting the cover-page entry on the record's
condition is M4-27; and the funnel's facts step, which the accepted fetch record
names and no M4 criterion needs yet.
