`docs/adr/fetch-normalize-v2.md` is accepted, and this is the task it hands
on. The stage retrieves company facts for about one filer in twenty, because
EDGAR spells the `cik` of that document two ways and the reader takes only the
string; the open escalation says so, and the record decides what crosses
instead: one key, ten digits, read off the document in either spelling. On the
same version rides the field the accepted alignment record proposed,
`report_period_end`, the date the submissions document publishes as
`reportDate` for the filing a fact was reported in — the one field that lets the
cover-page share count be admitted at the period its filing is about and at no
other.

The record says what this diff is down to the shape of the fixture, and the
acceptance above transcribes it rather than adding to it. The two changes to
the surface and the second line in `versions`. The Rust beside the bytes moving
to v2. The reader taking both spellings and refusing what neither is. The join,
and the two ways the field is empty. The four checks the pair for CIK 0002003750
can hold and the fifth it cannot. And the number-spelled recording, which the
record puts in this task on purpose: no gate compares a field's meaning to what
fetch does with it, so a key later re-spelled while the bytes stood still would
be caught by that fixture and by nothing else.

Exclusive, and the only exclusive task in this batch, because it writes a
contract. The path is protected and grantable: the hook allows the write
because this file, as committed on `origin/main`, lists it under `owns`, and the
pull request still needs the human-approved label on the server, which no
agent applies. `crates/normalize/` is in the list because its tests build a
`Fact` out of the fixture's rendering and a `Fact` now has nine fields; nothing
the crate answers moves, and the one thing v2 lets it do — admit the cover-page
entry where the filing's own period of report ends on the instant asked for —
is M4-26, queued behind this.

A submissions document rides into each facts case because the join is real
only where the history is. For the first filer that document is already in the
tree, and it has to be that recording and not a fresh one: the record's third
check is that a 10-Q filed after the history was recorded carries the field
empty, and a history recorded today would name it. For the second the
recording is live, as M4-20's was, with the sandbox off for that one command
and nothing else. Not in this diff: any further recording, which M4-27 and its
successors take one filer at a time; Rule 3, Rule 1 and the restatement
fixture, which wait on the record superseding Rule 3; and any kind for the
filer recorded here, which is decided against different evidence.
