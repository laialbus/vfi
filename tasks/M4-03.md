`docs/adr/fetch-normalize-contract.md` is accepted, and it decides what fetch
hands normalize. Nothing of it is built: `contracts/` has never existed, so the
contracts gate has been running over an empty set since M2. This publishes the
surface it decided, which is the first contract in the repository and therefore
the task that gives `contracts/` its meaning.

The collision is the part that is not a transcription. The gate's rule is that a
contract is a directory under `contracts/`; the layout doc's rule is that
`contracts/` is itself a crate, placed at the root because the protected-path
list puts it there. Both are written down, they cannot both hold, and which one
gives is this task's to decide inside its own boundary. What is not inside it:
the protected-path list is never grantable, so a reading that needs that file
edited stops and escalates, and so does one that would take a check away.

Two mechanics worth knowing before the run rather than during it. The hook
grants a write to a protected path only when `tasks/M4-03.md` **as committed on
origin/main** lists that path under `owns` — the working-tree copy grants
nothing — and for bash it grants only where the entry equals the protected entry,
which `contracts/` does. And a protected path that actually changes needs the
human-approved label at merge, which no agent may apply; the reading that leaves
the gate file untouched, if it is sound, is the one that does not wait on a
signature.

Exclusive because it creates a shared surface and may touch the gates, which
WORKPLAN.md single-threads.

What follows this task and is not in it: the type the stages compile against and
the drift check that keeps it honest against these bytes, the retrieval that is
the funnel's fourth step, and the golden fixture that proves fetch filters
nothing and that no two facts collide on their five identifying fields. The
record names all three as gaps nothing checks yet. They are later tasks, and
they are shaped by where this one puts the crate.
