---
id: M3-06
title: Verdicts persist in an append-only journal behind the ledger interface
milestone: M3
owns:
  - crates/fetch/
  - Cargo.toml
  - Cargo.lock
  - .gitignore
depends_on: [M3-05]
exclusive: no
acceptance:
  - One implementation of M3-05's interface writes records to an append-only
    journal at a path the caller supplies. The engine holds no per-user state, so
    the path arrives as a parameter and is never read from an environment, a
    config file, or a constant.
  - The journal is never inside the repository and is never the metrics store
    that the analyze → store edge will write.
  - A record appends whole, and the journal reads back whole, in the order
    written.
  - A process killed mid-write costs at most the record it was writing: every
    record completed before it still reads back. This is proved against a journal
    with a torn tail, not argued.
  - Nothing is overwritten. A later verdict for the same filer and step does not
    replace the earlier one; both read back, and current state is the latest of
    them. A rejection reversed next month is two facts, not one correction.
  - The layout inside the file is the implementation's own business: nothing
    outside `crates/fetch/src/ledger/` opens that file, for reading or writing.
  - No test writes into the repository or reaches the network. A test's journal
    is created and removed by the test.
  - Nothing proved gets narrower: every existing gate, proof, and fixture case
    still passes, M3-05's included.
---

The ADR settles the shape — append-only, one journal, a caller-supplied path in
the engine's local data directory — and leaves the file layout beneath the fields
open on purpose, because that is the part still cheap to change while the only
journals are ours. So the three properties above are the contract: a record
appends whole, the journal reads back whole, and a killed process costs at most
the record in flight. How the bytes are arranged to make those true is yours.

The torn tail is the criterion worth the most attention, because it is the one a
green test suite will not notice missing. A journal is written by a long pass
over thousands of filers, which is exactly the kind of run that gets interrupted,
and a reader that refuses the whole file over a half-written last line loses
every verdict before it.

This lands in the same crate as M3-05 and after it, which is why it is ordered
rather than parallel. Nothing here changes a gate, and `scripts/gates.sh` is
protected and not this task's to touch.
