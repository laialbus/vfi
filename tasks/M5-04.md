acceptance:
  - The gate suite reads every Rust file under `crates/analyze/`, its tests
    and any build script included, and goes red on a name that reaches any of
    the five GOALS.md lists for M5, which are the filesystem, the environment,
    the clock, a process and a randomized hasher. The failure names the file,
    the line and which of the five it reached.
  - The names read for each of the five are written down in one place in
    `scripts/gates.sh`, each beside the one of the five it stands for. The
    compile-time forms that reach the same things, such as `env!`,
    `option_env!`, `include_str!` and `include_bytes!`, are each decided in or
    out there, with the reason. So is what counts as naming a randomized
    hasher, given that std's `HashMap` and `HashSet` default to one.
  - Each of the five has its own proof-of-catch, a line naming it planted in a
    copy of the tree that turns the check red. One of the five with no planted
    case is not checked.
  - What the check cannot see, such as an alias, is said beside it, as the
    egress gate says it of its own.
  - The check runs from `scripts/gates.sh`, so CI runs it. If it is a new gate
    name, that name is in the expected gate set with its proof. If it extends
    `purity`, purity's existing proof still runs unchanged.
  - The network is the egress gate's, workspace-wide, and nothing here
    duplicates or narrows it.
  - 'Nothing proved gets narrower. Every existing gate, proof and
    `scripts/tests/` case still passes, and no entry leaves `denied_packages`,
    `allowed_edges` or the expected gate set.'
  - No crate, manifest, lockfile or source under `crates/` changes. The analyze
    source on main today passes as it stands.
---

GOALS.md's third M5 criterion, and the only one it orders: "checked, not
intended, and it is in place before the first metric is written." The purity
gate denies analyze the packages that reach the outside world, and its own
comment says what that leaves open: std's `fs`, `env`, `time` and `process`
come with every crate, and no dependency list can deny them. This closes that
gap for the one crate anchor 4 makes pure. The egress gate already reads source
for names, and it is the nearest precedent for the shape.

`scripts/gates.sh` is protected and grantable, so this task lists it under
`owns`. The pull request merges only with the `human-approved` label, applied
by a human hand.
