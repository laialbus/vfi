acceptance:
  - A fixture harness runs every fixture under fixtures/ and compares the
    output against its committed expected result. Fixture inputs and expected
    results are data under fixtures/; the harness is code and lives with the
    crate it exercises, per docs/layout.md.
  - At least one minimal fixture and its expected result are committed, so the
    whole loop — read input, run, compare — is exercised, and that baseline is
    the committed one. The real fixtures accumulate in later milestones.
  - A mismatch is a gate failure. Proof-of-catch, a scratch copy with a
    perturbed expected result turns the single command red, running with the
    gates in CI.
  - The gate runs from scripts/gates.sh and CI runs the same command.

This is the "golden fixtures still produce their expected results" gate from
AGENTS.md, built while the pipeline is still nearly empty — which is the
point: the harness must exist before the first real normalization work lands,
not after.
