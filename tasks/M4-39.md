The 2026-09-18 planner entry names this as the first of two open questions
standing between the wiring and the fixtures: "how a 6,765-line `expected` gets
written by something other than the code it checks". Nothing has answered it
since, and the milestone's last unmet criterion is the six fixtures, so the
question is on the path and not beside it.

It is above a worker because the answer decides what the fixtures gate proves
for this stage. The fetch harness has a recording to read against and normalize
has none; whatever stands in its place — a second reading of the rules, a
derivation checked only where a record pins it, or something else — is a
decision about a gate's meaning, not an implementation choice inside a crate.
A fixture task that settled it in passing would settle it for all six.

Not in this diff: any fixture, the harness, and the implementation of whatever
the record decides. The record is a proposal; the decider reviews it, and the
work it hands on is queued after it is accepted.
