acceptance:
  - Given a ticker, vfi-fetch returns that company's filing history as EDGAR
    publishes it. EDGAR keys on its own identifier, so resolving the ticker to
    that identifier is part of the work.
  - A ticker EDGAR does not know, and a company it knows with no filings, are
    each a stated outcome. Neither is a panic, and neither is a guess at which
    company was meant.
  - Every record carries where it came from — the request that produced it —
    so a later stage can trace a value back to its source without asking the
    fetcher again.
  - The behaviour is pinned by golden fixtures under `fixtures/fetch/`, recorded
    from live EDGAR and committed as data. `scripts/gates.sh` runs
    `cargo test -p vfi-<stage> --test golden` for every directory under
    `fixtures/`, so a fixture directory with no golden target beside it turns
    the fixtures gate red.
  - Every request goes through M3-01's chokepoint; nothing added here opens a
    connection around it.
  - No test reaches the live network. The recorded responses are what the tests
    read, and recording one is a step you take, not a step a test takes.
---

This is M3's first criterion and its last one together: retrieval, and the
provenance every retrieved fact carries. They belong in one task because a
record's source is part of the record, and bolting it on afterwards means
deciding twice what a filing record is.

Record the fixtures from EDGAR itself rather than writing them from memory. A
hand-written response that is nearly the real shape is the failure mode this
project treats as worst: it passes a glance and is wrong underneath.

What a filing record becomes to the next stage is not settled here. That is the
fetch → normalize contract, and a contract needs an ADR and the human-approved
label that `contracts/` carries; until then the type is vfi-fetch's own.
