---
id: M1-06
title: Refuse field-key spelling variants in task frontmatter
milestone: M1
owns:
  - scripts/tasks.sh
depends_on: []
exclusive: no
acceptance:
  - A frontmatter line whose key differs from id, depends_on, or exclusive only
    by letter case or by whitespace before the colon refuses the whole listing
    on stderr at exit 3, exactly as a malformed exclusive value does today.
    "Exclusive: yes" and "exclusive : yes" are the observed cases.
  - Genuinely different keys (title, owns, acceptance, milestone,
    exclusive_reason) are still ignored, and a file with no frontmatter is
    still skipped.
  - Behaviour on well-formed task files is unchanged, verified against the
    current script on the same fixtures.
---

The class is named in the decider's final re-review on PR #18: `Exclusive:` and
`exclusive : ` are valid-looking spellings the parser silently reads as absent,
so an exclusive task is offered as ordinary while a claim is in flight. `id`
already fails closed (id-less frontmatter refuses); `exclusive` and
`depends_on` have no such backstop — a silently ignored `depends_on` variant
would offer a task before its dependencies merge, which is the same shape of
bug. Fail closed on all three.
