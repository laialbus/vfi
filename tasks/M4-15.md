`contracts/canonical-concepts/v1.toml` has been published and frozen since
M4-05, and nothing in the engine can read it. `vfi-contracts` says in its own
words what it is for — "one module per contract, holding the Rust the stages on
either side of it are written against" — and today it holds one module for two
published contracts. This closes that gap, exactly as M4-06 closed it for the
fetch surface.

The milestone asks that each concept resolve to one of three states and that the
two absences are never confused: one a correct absence, the other a mapping that
failed. The surface already says how that is kept true — each absence is
constructible only from a witness the other cannot obtain, and the two witnesses
come from disjoint inputs. Making that structural rather than a rule someone
remembers is the point of compiling it: an enum has no state to check for at run
time, because none can be constructed.

The crate's standing rule applies unchanged. The bytes are the source and the
type is written against them, so the module's own test is the comparison, not a
second transcription that agrees with itself. What the type states is the shape;
what the file states is the content.

Not in this diff: any use of it. Pointing a stage at the type is the work of the
run that resolves, and doing it here would put a stage edge in a diff about a
boundary.
