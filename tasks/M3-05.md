acceptance:
  - The ledger is reached through one interface, in `crates/fetch/src/ledger/`,
    carrying the two operations the ADR names: record one verdict, and read back
    what was recorded for one filer. No path to a recorded verdict exists that
    does not go through it.
  - One record carries every field the ADR fixes: which filer — the identifier
    EDGAR keys on, with the ticker and name as observed — which step judged it,
    the verdict, the reason with the values it was judged on, where that evidence
    came from, and when: the moment, the pass, and the version of the ruleset
    that judged it.
  - The three verdicts stay distinct: admitted, rejected, and not judged because
    the evaluation itself failed. A transport failure cannot be expressed as a
    rejection — merging those two is how a bad minute becomes a permanent
    exclusion.
  - A rejection cannot be recorded without its reason, and a reason is a named
    value carrying what it was judged on, not free prose. "Rejected" and nothing
    more is the record this interface exists to make unconstructable.
  - The step a verdict belongs to is one of the funnel's three — seed, metadata,
    history — and no verdict can be recorded without one.
  - An in-memory implementation exists for tests. It touches no disk and reads
    back what it was given.
  - A test can pin a record's moment without waiting on real time.
  - Nothing proved gets narrower: every existing gate, proof, and fixture case
    still passes.
  - No test added here reaches the network or the disk.
---

The premise is `docs/adr/filer-decision-ledger.md`, accepted. It settles what is
above a worker here — that the ledger is an interface fetch owns and is handed,
what one record carries, and that the records live behind that interface rather
than in the metrics store — so this task implements a decision rather than
making one. Read it first; the acceptance above is its Decision section restated
as things to check, and where the two disagree the ADR wins.

The field set is the part the ADR calls expensive to reverse, because a journal
on a real machine turns a changed field into a migration. Follow it rather than
improve it. A field it names that seems redundant today is one to keep; a field
it does not name is a proposal, and a proposal is an escalation, not a commit.

Nothing here changes a gate. The ADR's Enforcement section is explicit about
which half of this design is mechanical — the deps gate already refuses the edge
that would break it, unchanged — and which half is review. `scripts/gates.sh` is
protected and is not this task's to touch; a task that finds it needs one is
mis-scoped and stops.

What records through this comes next, in M3-07. Build the seam so the funnel
cannot reach a record except through it.
