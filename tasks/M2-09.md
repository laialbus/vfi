title: Assert the gate set against a checked-in expectation
milestone: M2
owns:
  - scripts/gates.sh
depends_on: [M2-03]
exclusive: yes
acceptance:
  - The set of gates the runner executes is asserted against a checked-in
    expected set, defined as data in one place. A gate present in the
    expectation and missing from the runner — or the reverse — turns the
    single command red before any gate runs, naming the difference.
  - Proof-of-catch, a scratch copy with a gate deleted from the runner's list
    goes red, running with the gates in CI like every other proof.
  - Adding a gate legitimately means updating the expectation in the same
    diff — one more signed line in the same protected file, which is the
    point.
  - The gate runs from scripts/gates.sh and CI runs the same command.
---

Closes the blindness the decider recorded reviewing PR #27: the proof loop
iterates the same list the gate loop does, so deleting a gate deletes its own
proof and the command exits 0 claiming every gate passed. The runner is solid
against a gate being weakened and blind to one being removed. That was
tolerable while only a human could write this file; under the owns grant
(docs/adr/protect-paths-owns-grant.md) workers write it on every remaining M2
task, and the difference between weakened and removed should not rest on a
reviewer counting lines.
