GOALS.md's fourth M5 criterion names returns on capital, and
`docs/adr/which-other-period-a-metric-reads.md`, accepted on 2026-10-14,
is the rule they read a second row under. The rule finds a duration's
opening instant by stepping its start back one day, and it fixes where
that step lives: "one module of the derivation, `crates/analyze/src/date.rs`",
"the only place analyze reads a date", with "every number it needs" in
`constants/calendar.rs` under the RFC 3339 citation. This task builds that
module and that file, and nothing that reads them.

Why the reading comes first and alone. It is the one part of the rule that
reads characters as something other than an amount, and the record fixes
it to the digit: the grammar, the step, the leap year, each test start and
what it gives, and the one condition a start outside the grammar meets.
Every later reader of a date, the share-basis rule and the preceding-
duration record included, reads through this module, so it is built once
and proved on its own before the first seek depends on it, as the
arithmetic (M5-17) was built before the first metric (M5-18).

It depends on nothing because everything it reads is on main: the accepted
period record, the accepted arithmetic record whose reader it borrows the
radix from, and the three places the literal lint allows. A module no
metric reads yet is dead code until M5-29; how that is allowed inside the
crate is this task's to decide.

If the reading cannot be built without a number beyond the record's list,
a change to a contract, to `method.rs`, to `settings/` or to the entry
shape M5-18 fixed, that is an escalation.
