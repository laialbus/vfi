---
id: M1-09
title: Sweep the stale worktrees
milestone: M1
owns:
  - .claude/worktrees/
depends_on: []
exclusive: no
acceptance:
  - Every worktree under .claude/worktrees/ whose checkout is clean — no
    modified files, no untracked files — and whose work is finished (its
    branch's PR merged or closed and the branch gone from origin, or a
    detached HEAD) is removed with git worktree remove, never a bare rm, and
    git worktree prune has run.
  - A worktree that is dirty or holds untracked files is left in place and
    named in the session entry. Review harnesses and evidence are never
    deleted.
  - Local branches whose work is merged or whose PRs are closed, left behind
    by the removed worktrees, are deleted. Anything else is left.
  - The repository diff is this task file and the session entry; the rest of
    the work is local state.
---

Fourteen worktrees from the M1 and review sessions sit on merged work as of
2026-07-30, all clean. The frictions proposal flagged the missing sweep rule;
this is the worktree analogue of WORKPLAN.md's abandoned-claims rule for
branches. The standing "never delete a directory under .claude/worktrees/"
instruction protects live checkouts — owning the path in this task, with the
clean-and-finished test above, is the authorization to remove the dead ones.
This task only makes sense in the checkout that holds those worktrees; a run
whose .claude/worktrees/ is empty should leave this task unclaimed rather
than claim it and do nothing.
