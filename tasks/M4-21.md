`NotApplicable` is one of the three states this milestone requires, and no filer
in this repository can reach it today. The published vocabulary makes that state
constructible only "from a filer kind together with the applicability clause
below that excludes that kind", and `docs/adr/tag-concept-registry.md` says where
a kind comes from: "a `kind` field in the filer's file, asserted like everything
else there... A filer has the kind its file gives it; a filer with no file has
none." The per-filer half holds no file at all, so every concept for every real
filer resolves through the attempt — safe and imprecise, as that record says of
an unassigned filer, but it leaves the third state reachable only by a test that
names a kind for itself.

The filer the facts fixture is recorded from is the one to assert first, because
its statements are the only ones in the tree to argue from. The argument is the
vocabulary's own clause for the kind read against what that filer reports —
which balance sheet shape its facts describe, and which income statement they run
through — and it belongs in the file, beside the assertion, where the next reader
finds it without going looking.

What a filer file may hold is already fixed, and the registry gate is what fixes
it. A ground that needed a new field would be a change to the shape of the data,
which is an ADR and not this task; a comment is not. Nothing else rides along
either: an `include`, an `exclude` or an `assert` in this diff would be a mapping
judgement smuggled in behind a kind, and the two are decided against different
evidence.
