milestone: M3

  - crates/fetch/

acceptance:
  - The hosts vfi-fetch may reach are listed in exactly one place, and every
    request it makes passes that list before a connection is opened.
  - A host that is not on the list is refused as a stated outcome — not a
    panic, not a silent skip — and the refusal says which host was withheld.
  - The refusal is structural, not one test: a call site that reaches the
    network around the chokepoint turns the gate suite red. A test that
    exercises only the chokepoint proves the list works and says nothing about
    the path that skipped it, which is the difference between checked and
    intended.
  - Anything added to scripts/gates.sh carries its name in the expected gate
    set and its own proof-of-catch, like every gate already there.
  - No test added here reaches the live network. The gates run in CI and must
    give the same answer with the network gone.
  - Nothing proved gets narrower: every existing gate, proof, and corpus case
    still passes.
---

M3's second criterion is the one that says "checked, not intended". A list the
code is trusted to consult is intended; a list it cannot get around is checked.
The list this task builds is the engine's own — which hosts a filing fetch may
contact — and it is not the agent sandbox's allowlist in `.claude/settings.json`,
which is protected, is about what an agent's shell may reach, and is not this
task's to touch.

Everything later in M3 goes through what lands here: the rate limit that M3-02
adds sits at the same chokepoint, and M3-03's EDGAR requests are its first real
caller. Build the seam so a caller cannot opt out of it.

scripts/gates.sh is protected. If the work touches it, the pull request merges
only with the human-approved label, applied by a human hand.
