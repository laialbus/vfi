acceptance:
  - scripts/gates.sh exists. One invocation with no arguments runs every gate
    that has machinery today — the engine builds and all workspace tests pass —
    exits nonzero when any gate fails, and says which gate failed.
  - The ci.yml gates job runs exactly that command (toolchain setup aside) and
    the placeholder step is gone. The job keeps the name `gates` — it is the
    required status check.
  - Each gate the runner includes has a proof-of-catch, a test that injects a
    violation into a scratch copy and proves the command goes red. The proof
    runs with the gates themselves, in the same command, so it cannot rot.
  - Gates whose machinery does not exist yet — fixtures, benchmark, purity
    deny-list, contract compatibility, dependency direction — are absent, not
    stubbed green. Later tasks add them; nothing here pretends to run them.
