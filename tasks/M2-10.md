---
id: M2-10
title: Sweep releases claims without destroying work
milestone: M2
owns:
  - scripts/tasks.sh
  - scripts/tests/tasks.sh/
depends_on: [M2-07]
exclusive: no
acceptance:
  - A swept branch whose commits are all reachable from main is deleted, as
    today. It is a bare claim marker; nothing is lost.
  - A swept branch holding commits main does not have is renamed to
    escalated/<id>-swept-<timestamp>, never deleted. The claim is released
    either way; the record is kept.
  - The age rule and the open-PR rule are unchanged. Nothing younger than the
    claim lifetime is touched, and a branch with an open pull request is left
    alone.
  - The corpus pins both sweep outcomes, and proves the archived ref holds
    exactly the commits the claim held.
---

Sweep infers a dead run from age and a missing pull request, then applies one
destructive remedy to two different situations. The M2-07 handoff showed the
gap: a gates-green branch with no PR is indistinguishable from a dead claim,
and the deleted ref would have been the only origin copy of finished work.
Archiving is the project's existing principle applied — a record is not
something to tidy away — and the escalated/ namespace is already the place
sweep refuses to touch, so an archive can never be re-swept.
