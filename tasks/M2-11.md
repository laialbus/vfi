acceptance:
  - Every gate reports its own wall-clock time in the runner's output, on
    every run, so the next cost problem is measured instead of inferred.
  - The full suite, proof-of-catch included, completes in under ten minutes
    on the fleet machine. The M2-07 handoff run took over three hours end to
    end against a one-hour worker budget.
  - Nothing proved gets narrower. Every corpus case still runs against a
    pristine repository, every violation still turns the single command red,
    and no case, gate, or proof is removed or weakened. Cheaper setup — a
    template repository cloned per case, cases run concurrently — and proof
    runs scoped to the gate that owns the violation are acceptable; dropped
    coverage is not.
  - The proof-of-catch demonstration in the pull request shows the same
    catches as before the change, with the timings alongside.
---

The suite's cost is multiplicative: proof-of-catch re-runs the set once per
gate, and the scripts corpus builds a scratch repository with a bare remote
per case, per run — and both factors grow with every gate added. A worker
that cannot run the gates inside its turn cannot honestly reach the
definition of done; that squeeze is what pushed the M2-07 agent into the
background-monitor gamble its escalation records. Instrument first, then take
the mechanical speedups. If the floor is still above the budget after that,
stop and escalate with the numbers rather than trading proof for speed —
raising the wall clock is a human decision, and it should follow a
measurement.
