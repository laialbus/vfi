`docs/adr/candidate-choice.md` is accepted and it draws this record's boundary
in one sentence: "Alignment names a period and a filing. This rule turns that
pair into a value or an absence." Everything on the far side of that seam is
undecided, and the milestone asks for it by name — amendments, restatements and
period alignment following a stated ruleset, separate from the mapping.

The seam is drawn where it is because of what the fetch boundary withholds: a
filing publishes many durations and many instants, and nothing in the eight
published fields says which of them is the year the filing is about. The
candidate-choice record refused to pick one from inside a filing — the longest
duration, the latest-ending, the one nearest 365 days — because each reads well
and is wrong for some filer. So this record is where that question is answered,
with `form`, `filed` and `accession` in hand and a whole history to read rather
than one filing.

This is a proposal, not an implementation, for the same reason its three
predecessors were: a ruleset that decides which filing answers a period is above
a worker, and a run that wrote it into code would be deciding it in the file
nobody would think to check. The decider accepts or rejects; the run that
implements it is a later task.

Where the record is unsure, it says so and stops rather than picking the reading
that lets the next task start. This is the part of the milestone where a
plausible-looking wrong answer is the failure mode: a restatement silently
preferred the wrong way produces numbers that look right for years.
