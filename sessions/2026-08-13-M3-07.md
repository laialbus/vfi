# 2026-08-13 — M3-07

Branch `M3-07`. `vfi-fetch` gains `funnel`, with the first two steps of it:
`seed` reads the filers there are out of EDGAR's ticker map, and `gate` judges
each one on what EDGAR publishes about it. Both record a verdict for every filer
they reach, through M3-05's interface.

The gate applies one exclusion and it is GOALS.md's, cited where the constants
are defined: a filer whose newest annual report is a 20-F is a foreign private
issuer and is rejected; one whose newest is a 10-K is admitted; one whose
metadata names neither is not judged, which is not a rejection. Neither is a
metadata document that did not arrive.

The step boundary is a type. `edgar::metadata` hands back `Listed` — a form and
a date — and not `Filing`, so the metadata document cannot stand in for the
history the next step retrieves, and the pages of older filings it names are
never followed. A rejected filer costs the one request its verdict was read out
of.

What one step hands the next is the keys it considered, never who it kept.
`funnel::admitted` reads that back out of the ledger, so there is no path by
which a filer reaches the next step unrecorded.

Three fixtures under `fixtures/fetch/`, recorded from EDGAR: one filer admitted,
one rejected, one that could not be judged. A funnel case's seed document is
EDGAR's map with rows removed and none added — a pass over all ten thousand of
them would want a recorded metadata document apiece. `expected` was written from
the recordings by a reader that is not this crate, as the harness requires.
