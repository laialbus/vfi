# 2026-09-06 — M4-13

Branch `M4-13`. Every entry in the general mapping now states how it reads its
concept, `exact` or `stand_in`, and the cover-page share count states that it
answers the period of the filing it was reported in — the one entry that answers
anything but the period asked for. The registry gate refuses an entry with no
reading, either field outside its closed set, and that period answered on a
concept the published vocabulary does not measure as a balance, each with its own
proof-of-catch. The reader behind the one interface refuses the same and carries
both fields out with every eligible rule, reading neither: nothing is ranked,
dropped or preferred for either, and nothing resolves.

The spellings, which `docs/adr/candidate-choice.md` left to this task:
`reading = "exact" | "stand_in"`, and `answers = "period_asked_for" |
"filing_reported_in"`, written only where it is not the default. Neither is in a
rule id — they say how a rule is read, not which rule it is — so no stored id
changes. The parser state in `read.rs` is now `Reader`, so `Reading` names one
thing in that file.

For the decider. Thirty of the seventy-five entries are `exact`. Two concepts
came out in the shape the record names for `capital_expenditure` rather than for
`revenue`: `long_term_debt` names borrowings *and* finance leases and no element
carries both, so the sum of the two is exact and each tag stands in. Where a
concept has an element that names it whole, that element is exact and a sum
rebuilding it stands in. Three concepts have no exact entry at all —
`cash_and_equivalents`, `dividends_declared_per_share`, `preferred_equity` —
each on a clause of its own meaning that no element it lists covers for every
filer; each file says which clause.
