# 2026-08-01 — M2-05

Branch `M2-05`. `scripts/gates.sh` gains the `fixtures` gate, in AGENTS.md's
own position for it — after `tests`, before `deps`. A fixture is a directory
under `fixtures/<stage>/` holding a committed `input` and `expected`; the
harness that runs them is that stage's `golden` test target, per docs/layout.md.
Which harnesses run is read off `fixtures/` rather than listed in the runner, so
a stage directory whose crate has no `golden` target is red rather than
unnoticed.

The harness is kept out of what `cargo test` selects (`test = false`). "All
tests pass" and "the golden fixtures still produce their expected results" are
two gates in AGENTS.md, and run together a mismatch would report the test gate
red and leave this one a name that can never go red alone — which is what its
proof of catch exists to rule out. The proof perturbs a committed expected
result in the scratch copy; an empty `fixtures/`, an empty stage directory, and
a stage with no harness are red too.

`vfi-normalize` gains the entry point the baseline fixture drives, and it
resolves nothing: the tag registry that would change a filing is data and is
M4's, and inventing a rule here to give the stage something to do is the guess
that looks right. `nothing-resolves-yet` pins that, so the change landing the
first mapping rule is the change that states a new expected result.

`scripts/gates.sh` is protected and this task owns it, so the pull request needs
the `human-approved` label.
