# 2026-09-05 — M4-11

Branch `M4-11`. `vfi-normalize` gains `registry`, the one way to the tag
mapping: given a filer, its kind, a concept and a period it answers with the
eligible rules each carrying its id, or with the value an override asserts, and
every answer names the version. The version is a sha256 over the files under the
root, path-ordered, computed where the bytes are read so it names the bytes that
answered. The reader refuses what the gate refuses; a registry with a defect in
it does not load. Nothing resolves, and the golden fixture is unchanged.

The eligible set comes back in id order, which is the order that says nothing —
sorted, deduplicated, and never ranked. Rules are compared and excluded by id
alone, so `include` and `exclude` compose to one set however they are written.
SHA-256 is written here rather than taken from a library: it is the one piece of
work whose correctness is fully pinned by published vectors, and the four NIST
ones are the test.

For the decider. Three readings the acceptance does not spell out. The period is
part of the question, because an assertion applies to the period it names and no
other, so an answer that could be an assertion has to know which period is
asked about. `kind_of` sits on the same interface, because the vocabulary routes
kind assignment to this registry and the kind is an argument to the lookup — the
day a kind is derived rather than asserted, the lookup does not change. And an
answer that is an assertion carries its source, because a number entering
normalize with no tag behind it and no stated ground is the bare uncited value
anchor 5 bans.
