# 2026-08-14 — M3-09

Branch `M3-09`. `Https` is the transport that reaches a real source: HTTP/1.1
written out over TLS, inside `crates/fetch/src/egress/`, the one directory the
egress gate allows a connection in. It connects to `Cleared::host()` and asks
for `Cleared::target()` — a new method that cuts the path where the cleared host
ends — so nothing reads the URL a second time. Certificates are verified and no
caller can say otherwise. No redirect is followed: a 3xx is handed back as the
answer it is, and following one means going out through `Egress::fetch` again
for the new URL.

For the decider. The dependency is `native-tls`, taken by `vfi-fetch` alone.
What was weighed against it: a client library — `ureq` and the rest — is handed
the URL and finds the host itself, which is the second reading the chokepoint
exists to prevent, so only TLS comes from a crate and the HTTP above it is
written here. `rustls` with `webpki-roots` was the other TLS candidate; it would
commit a copy of the root list to go stale, where the platform trust store does
not.

Two judgements beyond the criteria, both against a wrong answer that looks
right: a body under a transfer or content coding this cannot undo is an error
rather than a document handed on, and a socket that goes quiet costs thirty
seconds rather than the night. The cases drive the exchange over a stream held
in memory rather than a loopback server — the sandbox a worker runs under will
not open a port, so loopback cases would pass in CI and fail every local gate
run.
