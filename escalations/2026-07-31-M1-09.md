# Escalation: M1-09

- Date: 2026-07-31
- Branch: M1-09
- Commit: 1ad9e3b

Claimed M1-09, "Sweep the stale worktrees." Nothing was swept and nothing was
removed.

**What stopped me.** This run is a fleet worker. The wrapper clones each worker
into a fresh checkout under `vfi-work/worker-<id>`; that checkout has no
`.claude/worktrees/` directory at all, and `git worktree list` reports only
itself. There is nothing here to sweep. The fourteen worktrees the task
describes are in a different checkout of this repo on the same machine — the one
the wrapper sits beside — which is outside this run's workspace, where both the
sandbox and the pre-edit guard refuse writes. The task file names this case and
says such a run should leave the task unclaimed; but the claim is made by the
wrapper before any agent reads the task, so a worker cannot decline it in
advance.

**Why it will recur.** Every worker checkout is a fresh clone with no worktrees,
and workers draw from the pool at random. Left as is, M1-09 will be claimed and
released repeatedly, costing a run each time and never being done.

**What I would need to proceed.** Either the task is run from the checkout that
holds the worktrees — a lead or decider run there, or a human — or the planner
re-scopes it so the target checkout is a stated input rather than the run's own
workspace. The second option also needs authority to write outside the worker's
workspace, which no worker has and which is a containment change, not mine to
make.

The task file is left in the queue, since the task is not done.
