# Escalation: M2-02

- Date: 2026-08-01
- Branch: M2-02
- Base: 7dbcfb0

M2-02 owns exactly one path, `scripts/gates.sh`, and that path is protected. The
pre-edit hook refuses every write to it, so the task cannot land its own
deliverable. AGENTS.md says an agent that hits a refusal stops rather than
looking for a way around, so this run stops.

The gate itself is written and verified — `docs/proposals/gates.sh`, with the
evidence in its header. All that is missing is permission to install it.

## This is the whole rest of M2, not one task

`M2-03`, `M2-04`, `M2-05`, `M2-06`, and `M2-07` each list `scripts/gates.sh`
under `owns` too. Every one of them stops here for the same reason. M2 is "the
floor holds", and the floor is currently unbuildable by the agents queued to
build it.

Nothing in the queue is wrong: the planner scoped these tasks correctly, and
each is the right size. The collision is between the queue and the protected
list, and it was invisible until now. `M2-01` wrote this same file and merged
(PR #27) — its session entry records why it was not refused: the installed hook
exited 1 under Python 3.9 and refused nothing. PR #28 repaired the hook. The fix
was right, and it closed the only route M2 had.

## What I think the real problem is

The protected list has one entry consumed by two enforcement layers of different
strictness. The server-side check in `.github/workflows/protected-paths.yml`
allows a protected-path change carrying the `human-approved` label — a human
signs, the change lands, which is exactly how `M2-01` merged. The client-side
hook allows nothing at all; it has no notion of a signed change, because it runs
before there is a pull request to label.

For a file the queue expects six more tasks to extend, "no agent may write this"
is stricter than the policy the list is meant to express, which is "no agent may
write this *unsigned*".

## What I need

A decision. I am not writing the ADR for it, because the three routes differ in
kind and picking one is above this run:

1. **Drop `scripts/gates.sh` from the protected list.** Unblocks the queue
   immediately. The cost is real: gates.sh *is* the enforcement machinery, and
   "do not weaken a gate to make it pass" stops being structurally hard and
   becomes something PR review has to notice.
2. **Keep it protected and let the gate tasks deliver drafts.** Each M2 gate
   task ends in `docs/proposals/` and a human installs it. Costs nothing in
   safety and serializes six tasks behind a human. This is what this run did,
   so route 2 needs no decision to proceed — only an acknowledgement that the
   cadence is intended.
3. **Teach the hook about `owns`.** Allow a write to a protected path when the
   run's claimed task file lists it. Workers do not write task files — the
   planner does — so this does not let an agent grant itself permission. It is
   the largest change of the three and wants its own ADR.

My recommendation: install this draft under route 2 now so M2-02 is done, and
decide 1 vs 3 before M2-03 is claimed, so the next five tasks do not each stop
here and write this file again.

## To close this

Install `docs/proposals/gates.sh` to `scripts/gates.sh`, keeping the executable
bit, and delete both the draft and this file. `tasks/M2-02.md` stays in the
queue until the gate is actually in place — this branch does not retire it.
