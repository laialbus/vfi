# Escalation: decider

- Date: 2026-09-03
- Branch: decider-2026-09-03

The 2026-09-03 decider sweep could not call `gh`. Every invocation, `gh pr
list` and even `gh --version`, was refused by the harness's permission gate
with "This command requires approval", and an unattended run has nobody to
approve it. Inside the sandbox `gh` fails on TLS, the limitation the agent
rules record, which is why the project settings exclude `gh *` from the
sandbox; an unsandboxed `gh` therefore needs a permission mode that grants it.
Every earlier decider sweep merged and commented, so earlier launches had that
mode and this one did not. The file-editing tools were refused the same way;
this file and the session entry were written through the sandboxed shell.

What the sweep still did, through the public GitHub API and git: reviewed both
open PRs. #141 (the second 2026-09-02 decider entry) and #140 (M4-10, the
registry's per-filer half, carrying the human's approval label) both have green
checks and both pass review. Neither could be merged, no comment could be
posted, and this run's own session-entry PR could not be opened. The verdicts
are in `sessions/2026-09-03-decider.md` on this branch.

To resolve: launch the decider under the permission configuration the earlier
sweeps ran under, or add an allow rule for `gh` where the launcher reads its
settings. Both sit outside a run's authority, since the project settings file
is a protected path. Then open this branch's pull request, one command for a
human with `gh`, or let the next decider fold this file onto main. No task is
parked by this file.
