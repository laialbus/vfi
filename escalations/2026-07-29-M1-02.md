# M1-02 — no Rust toolchain, and no gate that would catch it

**Task:** M1-02, create the Rust workspace with one empty crate per stage.
**Stopped at:** preflight, before writing any file. Nothing was changed.

## What stopped me

There is no Rust toolchain on the machine. `cargo`, `rustc`, and `rustup` are all
absent from `PATH`, and there is no `~/.cargo`, `~/.rustup`, Homebrew, or
`/pkg/env/global` install to fall back on.

That alone would only be an inconvenience if something else checked the build.
Nothing does. `.github/workflows/ci.yml` is still the M2 placeholder — its
`gates` job echoes a line and exits green — so a Cargo workspace merged today is
verified by no one. The task's first acceptance criterion is that the workspace
compiles under `cargo build`, and I can satisfy it neither locally nor in CI.

Writing four `Cargo.toml` files unverified is not the small risk it looks like.
`Cargo.lock` is a generated artifact; hand-writing one is guessing at a
generated file, which is the failure mode AGENTS.md names — a plausible-looking
wrong answer that passes a glance. So I stopped rather than ship the workspace
behind a gate that cannot fail.

## What I would need to proceed

Either one is enough, and the first is the smaller change:

1. **A Rust toolchain on the runner box.** Installing one is outside an agent's
   reach twice over: it writes to `~/.cargo` and `~/.rustup`, outside the
   workspace, and it downloads from `sh.rustup.rs` / `static.rust-lang.org`,
   neither of which is in the `.claude/settings.json` network allowlist. A human
   installs it (`rustup` via the official installer); no repository change is
   needed. Whether the allowlist should also gain those two hosts, so a future
   agent can install or update a toolchain itself, is a separate call and I am
   not making it here.

2. **A real build step in CI.** This is M2's job — `scripts/gates.sh` and the
   `gates` workflow body — and both are protected paths. Pulling that work
   forward into M1-02 would be a second task in one run and a protected-path
   edit, so it is not mine to do.

## What I did

Claimed M1-02 by pushing the branch, found the blocker, wrote this, and released
the claim by deleting the branch. The task is unchanged and back in the queue:
`tasks/M1-02.md` was not deleted, and no workspace files were created. Whoever
picks it up next needs only a toolchain to be present.
