**What stopped it.** The task's seventh criterion: where the crate builds a
state v2 has no place for, the run does not invent a crossing, and unless
M4-37's merged surface states one it stops. It states none, and there are two
such states.

An `Unknown` is built from `Attempts::in_filings(first: Attempted, rest)`,
which holds at least one attempt, and `undecided_by` hangs a `Tie` on an
`Attempts` that already exists
(`crates/contracts/src/canonical_concepts.rs:299`). Its own doc line makes the
emptiness deliberate: "an `Unknown` with nothing attempted is the empty case
the published state set closes itself against."

But `standing::latest` returns exactly that emptiness in two places
(`crates/normalize/src/standing.rs:254`, `:220`). The gap is narrow and
precise: **where Rule 3 ties and *every* answering filing produced a `Value`,
`attempted` is empty** — the tied filings succeeded, so none of them is a
failed attempt — leaving no `first` to build an `Attempts` from and nowhere to
put the tie. `Undecided::Undated` is empty for the same reason. Where some
answering filing came to `Unknown`, `attempted` is non-empty and both cross
fine; the gap is only the all-valued case.

This is not a defensive branch. The task asks for a hand-written tie case, and
the merged test
`a_same_day_tie_no_form_breaks_is_unknown_carrying_both_accessions_whatever_the_figures_say`
(`crates/normalize/tests/standing.rs:328`) already asserts
`attempted().is_empty()` beside `Undecided::Tie`. No merged fixture reaches
either state, but the required test case does, so it cannot be left unreached.

**The reading not taken.** Crossing a tied filing as
`Attempted::in_filing(accession, Attempt::that_ran(vec![]))`. v2 reads that as
an attempt that considered no candidate; these considered one and found it, so
it would collapse two cases v2's own `Unknown` line keeps apart. Listing the
tied candidates as `Declined` would be worse: `Declined` names the rule that
declined a candidate *inside one filing*, and a cross-filing tie declines
nothing.
